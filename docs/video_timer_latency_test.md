# 大数字计时器视频输入延迟测试

本工具替代实时二维码解码：屏幕显示六位大数字（单位毫秒），接收机连续取帧并立即打本机单调时钟时间戳。正式采集期间不做数字识别、模型推理、图像压缩或磁盘写入。只把每秒约5张原始帧存入内存，45秒结束后才保存PNG并离线读数字。

## 开始

双击项目根目录 `start_video_timer_test.bat`。默认USB Video编号0、DirectShow、640×480。重插设备可能改变编号；先看回传是否来自图传相机。本机2026-10-22枚举为0=USB Video、1=HD Webcam。

1. 把相机正对左侧SOURCE计时器，让黑色矩形边框与六位数字完整入镜，并尽量充满画面。
2. 回传预览应放在相机视野外，避免递归回传。如果屏幕太小，移动预览到别处或调整相机视角。
3. 点击测试窗口按空格：预热2秒、正式记录45秒。默认只预览，不自动开始记录。
4. 到时关闭采集窗口，保存数据，再自动离线读数；不要在保存完成前终止进程。
5. Q/Esc可提前保存；提前结束的记录明确标注不完整。

## 测量含义

每次数字更新都保存“数字值→imshow提交前时刻”的对应关系。离线从接收帧读取数字，精确查找本次运行实际发出的同一数值，计算：

`submit_to_capture_ms = (对应帧read返回时间戳 - 对应数字imshow提交时间戳) / 1e6`

因此不把数字绘制耗时、离线读数耗时直接计入测量值。六位数字只是毫秒标签，不代表显示器有1ms时间分辨率；默认软件目标更新60Hz，实际更新时间间隔记录在报告中。显示器刷新/合成、曝光混合与缓存仍会影响结果。

仍包含源显示器、相机、模拟图传、USB接收、驱动和取帧缓冲。源屏幕真正发光的时刻没有测量，不能随意扣除某个刷新周期。本工具不测YOLO推理、指令传输或舵机动作，也不能测出独立RF/接收机延迟。

本轮统计是定期抽取帧的画面年龄；上一版二维码统计的是唯一代码首次成功识别出现时间。二者采样方法不同，不能仅凭结果下降就宣称硬件链路变快。

## 保存与审核

每轮在 `outputs/video_timer_latency/时间_会话ID/` 独立保存：

- `summary.json`：采集设备、参数、完整性、实际源更新间隔与脚本哈希。
- `source_events.csv`：所有实际提交数字及时间戳。
- `frames.csv` 和 `frames/*.png`：抽样原始图像与对应取帧时间戳。
- `analysis.json`：采集结束后的初步自动统计；`visual_audit_status=pending`表示尚需人工核对。
- `samples.csv`：离线读数、分段置信指标、关联提交时间与延迟。
- `rejected.csv`：无法明确读取的图像。不得把读数失败解释为图传丢包。
- `audit_*_rectified.png`：前6个自动读数对应的透视校正画面，须与原始帧对照审核。

离线读数根据矩形边框做透视变换，再读取七段数字。模糊、混合数字、镜头畸变可能导致拒绝或误读；只接受本轮实际发出的数值，且时间差在0～5000ms以内。保留拒绝计数并提示延迟上限可能截断分布。没有有效数据时统计为null，不能写成0ms。自动读数不是已审核的实验结论，必须检查原图与数字对应关系；必要时根据原图人工标注后另行汇总。

2026-10-22离线读数补充：当固定七段位置无法读取时，允许每个数字做小范围平移模板匹配，最高相关分数至少0.72，且与第二候选数字分数差至少0.08。先根据图像独立确定数字，再核对本轮发出的数值与时间；不以希望得到的延迟选择数字。较小边框的最小检测面积改为画面2%。这些修改只影响离线读数，不改变已保存的原图、源事件或取帧时间。自动读数分数是图像匹配指标，不代表读数准确率。

可以不打开相机、单独重跑离线分析：

```powershell
& 'D:\app\miniconda\envs\python312\python.exe' tools/measure_video_timer_latency.py --analyze 'outputs/video_timer_latency/某次运行目录'
```

默认约225张PNG，在内存中暂存约200MB，采集结束后写盘。限制640×480、最多450帧。不发送任何串口/机械臂命令；原二维码测试工具及其记录保留。
